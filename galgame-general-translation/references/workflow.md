# 项目与子代理编排

## 1. 最小项目状态

先由材料和脚本入口确定范围、顺序、共通／个人线／真结局、可见字段、编码和输出要求。只补真正缺失的信息，不先发长问卷。沿用已有布局；新整线／全作项目可在工作区建 `.galgame/`：

```text
.galgame/
  project.json                  # 范围、归属、阶段、版本和模型；主代理写
  style.md                      # 简短风格、主要人物声音和称呼策略
  glossary.jsonl                # 唯一当前总表；主代理写
  decisions.jsonl               # 非平凡术语／歧义决策，按需创建
  snapshots/glossary.rNNN.jsonl  # 阶段交接处只读词表，不按句生成版本
  reviews/<scope-id>/            # 本范围一次纠错报告和分批覆盖；审核者写
  routes/<route-id>/
    state.json                  # 翻译／自审覆盖、位置和恢复风险；本线负责人写
    scan.jsonl                  # 本线扫描候选
    terms.local.jsonl           # 本线新增／挑战词条，仅有增量时创建
    fixes.jsonl                 # 审核问题处理、定向修订及局部自检，按需创建
    handoff.md                  # 有交接需要时才保存的短状态与原文引用
```

共通和真结局各有独立 scope-id。审核者不改译者状态；译者不覆盖审核者报告，修订另记。正文写入项目指定译文目录，不塞进状态文件。

索引保存真实文件／ID清单、源译版本、所有权、扫描／翻译／自审／一次纠错覆盖和词表版本。用已有源译映射，避免重复巨型清单；按场景／合理批次保存必要衔接，不存全文剧情摘要。模板是记录示例，不是编排器。恢复规则见 [review.md](review.md)。

## 2. 路线与写入所有权

主代理负责共通、共用片段、UI 和其他非个人线，真结局例外留到最后。核实入口、跳转与解锁依赖，不能只凭文件名猜归属；未知文件标记待定，不丢出范围。

每条个人线包含所属普通／坏结局及明确归属的附加场景；独立隐藏个人线单独分配。共用脚本只翻一次，同原句但不同状态保留分支语境，不盲目复用。

一名翻译代理在本项目内只负责一条线路，不跨线兼任、不再拆本线给子代理；每条线同一时刻一个正文写入者。扫描与翻译代理可不同，审核者是新上下文，只审自己的范围、只写报告，也不让其他线译者交叉代审。审核者虽不写正文，仍占子代理名额；同线译者与审核者不得同时保持未释放线程。

不同线路混在同一文件时按“文件＋稳定 ID”分配，各线输出独占补丁，由主代理串行回填。确认文件集完全不相交时才允许各线直接改独占译文。子代理不改总词表、全局索引或共享原文件；工作流写入约束不等于操作系统沙箱。

## 2.1. 单线路单槽位与交接

**每个 scope-id 同时最多一个占用名额的子代理；创建、关闭和恢复均由主代理执行。** 主代理本身不是这条线的第二个子代理。不同线路可并行，但全项目须遵守宿主实际总上限及其他已占名额；不得为了赶工自动调高配置。

“等待”“任务已完成”“没有输出”均不自动等于名额释放。切换角色前先保存产物及检查点，再用宿主实际支持的关闭／释放操作，收到明确成功或槽位释放证据后才启动下一角色。Codex 暴露 `close_agent`／`resume_agent` 时按实际工具契约调用；不要把中断本轮或删除聊天当成释放，不能凭工具名保证所有客户端都支持恢复。

固定交接顺序：

1. **翻译结束：** 译者保存译文、自审覆盖、线内术语和恢复依据；主代理记录原线程 ID／恢复定位与实际模型配置，关闭译者并确认释放。等待其他线路或主代理统一术语时只保留记录，不保留占槽译者。
2. **术语返修：** 只有确需修改时，主代理排队恢复原译者；它修订并自检后再次保存、关闭和释放。冻结本次待审稿，再进入审核。
3. **整线审核：** 本线槽位已释放且全局有空位时，主代理新建无翻译聊天历史的审核者。同一审核者完整读完本线，允许内部顺序分批保存覆盖，但只在整线完成后一次交付完整问题清单与覆盖。期间不恢复本线译者，不边审边返修，也不让审核者自行召唤译者。
4. **交卷与释放：** 主代理检查报告文件可读、绑定正确版本且覆盖完整，不再重审正文；随后关闭审核者并确认释放。在此之前不得恢复本线译者，也不得让双方同时等待彼此。
5. **修正与结束：** 有问题需要处理时，主代理优先恢复登记的原翻译线程，交给它完整报告及当前词表／稿件；按恢复规则核对原文、模型和状态，再修正或有证据驳回，并自检影响范围。落盘后关闭释放，不重新召回审核者。报告无问题且无待改项时可直接完成，不无故唤醒译者。

扫描代理同样交付后关闭释放，再分配下一条线；等待全部扫描定词时不占槽。后期词表变更需返修另一线时，若该线审核仍在进行，只登记待办、不改冻结稿；等它完整交卷并关闭后，将术语修改与该线问题一起交原译者处理。补审未覆盖区段也必须先释放译者、补齐覆盖并关闭审核者、再恢复译者，不能以“补审”为由同时开两个。

主代理在 `project.json.agent_scheduling.scope_slots` 维护精简登记，不另造一套正文状态：每项用 `scope_id`、`translator_thread_id`／`translator_resume_ref`、`translator_handoff_path`、`reviewer_thread_id`、`active_agent_id`、`active_role`、`slot_state`（`occupied / release_pending / released_confirmed / unknown`）、`last_release_evidence` 与必要报告路径。登记原译者 ID 不是让它保持打开；正式配置仍从本线 owner 读取。创建／恢复前先登记占用意图；工具返回不明确时标 unknown 并核实，不能重复派发。

关闭失败、槽位释放未确认或容量不足时，先核对本任务可管理的线程，清理已完成线程或排队；未知状态保守当作占槽。不得擅自关闭用户其他任务，不为探测额度反复 spawn，不用另开顶层会话／外部进程绕过上限。若宿主无法释放名额，报告限制，不声称本约束已实现。

恢复优先使用原线程／官方支持的会话恢复；恢复后核对当前实际配置，不能把有记忆当作无需读稿。宿主明确不支持或实际恢复失败时，先确认旧线程释放，再用同配置、同线路的替补读取落盘依据，记录为替补而非原代理已恢复。无同配置可用时报告限制，不能静默换模型。

异常中断的报告标 partial，不能冒充一次整线完成后交卷；保存已审覆盖并确认旧审核者释放，优先恢复该审核任务补齐未审内容。若关键缺件必须先由译者修复，先保存并关闭审核者，再由主代理串行安排修复和继续审核，保留版本差异与未覆盖记录；这是明确异常处理，不是常规边审边改。

## 3. 模型、推理档与授权

记录主代理实际型号／推理档和个人线基础配置。用户指定优先；只指定一项时按下表补另一项并验证支持情况，不把同型号当同推理强度。

| 阶段 | 用户未指定 | 用户只指定模型 |
| --- | --- | --- |
| 个人线扫描 | 可确认的最便宜可用模型＋该型号最高支持档；不能可靠选择则两项回退主代理 | 指定型号＋其最高支持档 |
| 个人线翻译 | 主代理型号＋推理档 | 指定型号＋主代理推理档，须支持 |
| 真结局 | 个人线基础翻译配置，不沿用扫描配置 | 指定型号＋个人线基础推理档，须支持 |
| 一次整线纠错审核 | 被审范围实际译者型号＋推理档；共通跟主代理 | 指定型号＋该范围译者推理档，须支持 |

只指定推理档时仍按相应阶段选模型，再验证组合。明确指定的型号／档位不可用时报告限制，不私自换收费模型或降档。没有可比较价格时不拿 API 标价冒充订阅成本；扫描的“最便宜型号＋最高档”不保证总用量最低。

通过现有模型列表、实际工具参数、有效配置或返回值核对能力；必要时查提供方官方资料，不硬编码 Luna、Astra、价格或 `high/xhigh/max`。尽量显式指定型号和档位，注意自定义代理或全局默认的覆盖；分别记录 requested 和 effective。实际值不可观测就记 unknown，不声称核实成功，不自行改全局配置或开启新收费服务。

扫描者只有实际配置与正式翻译要求一致且所有候选已定词，才可恢复为本线译者；默认新建正式翻译代理。等待统一定词期间仍须关闭扫描线程并保留恢复信息，不能占槽待命。真结局沿用个人线基础配置，不继承个别线路的单独覆盖；各线无共同覆盖时保持原基础并说明。

没有授权不启用子代理。`subagents_requested` 控制分线路协作；可选 `review_subagents_requested` 为空时继承该授权，显式值仅控制审核。用户明确要求“翻完后新开审核子代理”即授权审核，但不自动授权把正文分给多个译者。用户禁止子代理或宿主无能力时串行降级并记录，不伪造代理完成。

## 4. 有分线路子代理时的顺序

### P0：确定范围与保护原文

识别全量范围和依赖、分配所有权、记录模型、保护源文件。先小样验证提取／回填和中文支持；现有工具足够就不重造适配器。

### P1：共通／非个人线

主代理顺序翻译，随译建总词表和简短人物／称呼基线；每完成一个场景或合理批次，对照原文自审本批全部新译单元，再继续下一批。无共通时处理确有的非个人线；两者都无就复用资料建最小基线，不虚构产物。

真结局不在此阶段。需要个人线后续信息才能处理的非个人线片段标 deferred，依赖满足后由主代理补译，将相关片段合为有意义的审核范围，不一小段开一个代理，也不得漏审。

共通完成并自审后，冻结稿件，新建无翻译历史上下文的审核代理，对照原译文做一次四类纠错。审核者完整交卷后，主代理先关闭它并确认释放名额，再根据完整报告修正并局部自检；审核期间不边审边改共通稿，不再召回审核者验收。记录未决，发布可用扫描基线。

### P2：各个人线预扫描

每线一个扫描代理，按扫描配置读完整本线原文、共通词表及术语协议，提取专业术语候选、最小证据和真实覆盖。只返回路径与精简摘要，不翻正文。

可并行、槽位不足排队分批；每名扫描者交付后必须由主代理关闭并确认释放槽位，再派下一任务。所有指定线扫描完成并由主代理统一定词前，不启动任何个人线正文翻译；真结局此时不混入普通线正文。

### P3：主代理统一定词

依 [terminology.md](terminology.md) 裁决同义、同形异义、称呼阶段与冲突。证据不足只补局部原文，不让主代理重读全部线路。发布统一只读词表版本和校验值。

新证据影响共通译法时由主代理定向修改、自检并留下版本差异，不再重启一次共通全文审核。未决候选不能当已批准；足以造成大范围不可逆错误的关键歧义先报告。

### P4：一线一正式翻译代理

按正式配置新建各线译者，提供只读词表、必要共通衔接、人物策略、本线原文与独占输出范围。不沿用便宜扫描模型作为默认，不把所有线路历史附入上下文。

按场景／合理批次翻译并自审本批全部新译内容，保存位置和衔接。漏扫新词写本线专用增量表保持一致，不改全局表、不每词打断主代理。返回文件路径、覆盖和未决，不将整线译文贴回主对话。

槽位不足排队分批；同一代理不接另一线。每线翻译和自审完成即保存本线恢复依据，主代理登记原译者线程与配置并关闭、确认释放。保留的是可恢复身份与产物，不是占槽待命的译者。全部个人线结束前使用同一翻译词表基准。

### P5：汇总增量与定向修订

全部个人线翻译、自审完成后，主代理一次性审核各线专用词表，无冲突新词合并、真冲突裁决，发布新总表。仅给受影响负责人发具体改词范围与证据；没有影响的线路不重译。

主代理在空闲名额内恢复原译者按语境修订并自检，无法恢复时按第 2.1 节同配置替补。修订完成保存产物，关闭译者并确认释放，稿件进入 ready_for_review；术语通过不能代替正文纠错。

### P5R：每条个人线只做一次纠错

每线冻结术语修订后的稿件，先确认原译者已关闭释放，再由主代理在总上限内新建不继承翻译聊天的审核代理；审核期间本线只有审核者占槽。它按正确场景／分支顺序完整对照本线原译文，只查错译、漏译、主语／指代错误、上下文不连贯。一次审核可分批，不按批再建代理，不另设全文中文风格审读。

审核者完整审完本线后一次返回完整精简问题清单及覆盖；不逐批把问题交译者返修。主代理确认交卷完整、关闭审核者并确认名额释放后，才恢复登记的原线路翻译代理核对并修正，改动处和必要上下文做局部自检，记录证据及处理结果；不默认让审核者复核返修，不另开第二轮。修订交付后原译者再次关闭释放。术语反证由主代理裁决，受影响各线按各自槽位排队修订；仍在审核的线不并发改稿。

有完整一次纠错覆盖、问题处理及修订自检、无实质阻塞后，标本范围完成。最终版本保留“已审稿＋修订记录”的关联，不写成新稿经过额外独立复核。缺审范围只补覆盖，不重复已审全文。

### P6：真结局

本次范围含真结局时，等待各个人线术语裁决、一次纠错及修正完成，并完成必要 deferred 内容，再委派一个真结局专属翻译代理，默认沿用个人线基础型号和推理档。

只交必要前置状态、原文引用和总词表，跨线玩家知识不是当前角色已知事实。可先定位关键新概念，无需另建扫描队伍；翻译中分批自审，新词用本线增量，由主代理裁决后原译者定向修订。

真结局完成后同样轮换单槽位：保存并关闭真结局译者、确认释放 → 新建无翻译历史的审核者完整做一次四类纠错 → 一次交卷并由主代理关闭、确认释放 → 主代理恢复原真结局译者修改及局部自检 → 保存并关闭。至此结束，不额外复核。后文证据改变早期译法时通知早期负责人定向修订、自检，保持揭示时机，不重开各线完整审核。

多个真结局片段若属同一连续线，交同一专属译者、合为一次完整审核范围；真正独立的多个最终路线各自一线一译者、一名新审核者，按脚本依赖执行。

### P7：汇总与技术检查

主代理核对所有范围、一次纠错覆盖、术语与问题处理记录，不再额外完整审一遍个人线或安排全文文风终审。只有确有证据的跨线未决问题才定向处理。

在最终文件上执行适用结构、解析、回填检查；有环境再做游戏实测。交付译文、总词表和简短检查报告，区分分批自审、一次独立／同代理纠错、原译者修订自检、术语、技术和运行未测。完成任务后清理本任务已结束子代理；未释放／释放未知、替补恢复、未审、抽检、未知隔离或重大未决如实列出。

## 5. 范围缩小、串行与恢复

只授权审核子代理时，正文按共通→个人线→真结局由主代理串行翻译，词表可直接维护，各完成范围仍新建审核代理完整做一次纠错，主代理先收完整报告、关闭审核者并确认释放，再亲自修正；不并行改正在审核的稿件。未授权任何子代理或明确禁用时，按相同两阶段执行但整线纠错记录 same_agent；不伪称新上下文。

只请求一条线／片段就只处理该范围；复用已完成依赖，不擅自重译全作。短片段默认直接译后自审；用户明确要求独立审核则按授权执行。

恢复时执行 review.md：核对实际文件、状态、词表和必要接缝原文，只补未完成和受影响内容。保留已有稿件及可靠审核记录；已有完整审核覆盖四类错误时不重复启动审核，只补缺失覆盖。不得把历史自检直接当独立审核。

## 6. 精简委派任务单

使用真实路径和值，不能让代理靠“见上文”猜，也不复制整段聊天：

