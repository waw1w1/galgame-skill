# 分批自审、一次整线纠错与上下文恢复

## 1. 只保留两个正文质量阶段

**边翻译边分批自审；整线完成后，新审核代理只做一次四类错误检查，原译者修改即可。** 修改后的局部自检属于修订本身，不另设审核者验收轮次。术语裁决和确定性技术检查仍执行，但不能替代原文对照。

### 翻译中的分批自审

“逐单元校订”是覆盖要求，不是调用频率：译完一个场景或合理批次后，由同一翻译负责人对照原文检查刚翻译的全部单元，修改后再继续下一批。批次依场景和可用上下文决定，不硬设极小字数，不每句另开代理，不等整线结束才自检。

自审覆盖语义、遗漏、主体与指代、自然中文与角色声音、关系／信息阶段、与上一批的衔接，以及标签和源译映射。全部新译单元都要覆盖；没有修改的单元不写逐句解释。记录“已翻译”和“已自审”范围，不能用一个状态冒充两个。

### 完成后的整线纠错

共通／非个人线、每条个人线、真结局均适用。使用子代理时，每个已完成范围只新建一名未参与其翻译的审核代理，完整对照原文和译文做**一轮**检查：

| 类别 | 查什么 | 边界 |
| --- | --- | --- |
| `mistranslation` 错译 | 否定、数量、因果、态度、事实、信息揭示时机，误添信息或把心理写成台词 | 不把有依据的自然改写当错译，不消灭原作有意含混 |
| `omission` 漏译 | 整句／条目遗漏、句中有效信息漏掉、文本错配造成的遗漏 | 不能只靠空译、字数或日文字符判断 |
| `subject_reference` 主语／指代错误 | 谁说、谁做、谁对谁；省略主语、代词、动作承受者及视角 | 原文本就无法唯一确定时保留歧义，不强补人名 |
| `continuity` 上下文不连贯 | 前后对话、动作、时间、位置、关系与称呼阶段；批次或压缩接缝；跨线事实污染 | 按实际分支与时间顺序判断，不把互斥结局拼成同一时间线 |

不额外安排完整文风、修辞、标点或人物声音终审；这些由翻译时自审承担。仅因“这样更好听”不立问题；文风或用词确实改变意思时归入上述错误。发现结构损坏可附带报告，不为此扩成另一轮文学润色。

## 2. 新审核代理不继承什么、仍须读取什么

新建审核任务时不继承主代理、译者或扫描者的聊天历史；不恢复译者会话充当审核者，不转发逐句推理、译者自我评价或整线剧情摘要。

优先使用宿主明确支持的新上下文／不继承历史的创建方式；是否支持及参数以实际工具契约为准，不能只发一句“忘掉上文”就宣称隔离。无法验证时记录 `context_isolation=unverified`；已知无法隔离时明确报告限制，按可用方式完成纠错但不得冒称无历史上下文。

“无历史上下文”不等于“没有审核依据”。提供本范围完整原文、待审译文、真实文件／ID清单、场景／分支顺序、冻结版本、适用词表及必要人物／称呼规则的路径。可附疑难位置、恢复边界和必要前置原文引用，但不先把译者结论作为答案交给审核者。

只读材料中，原文及可证实演出是事实依据；词表和简短资料是导航。需要共通入口或前置事实时按引用补读原文，不把所有个人线和主对话塞进审核上下文。审完整条线的过程本身建立该线语境，不能只读孤立句或只读译文。

审核模型和推理档默认与所审范围的译者一致，用户指定优先；不自动沿用便宜扫描配置。审核代理只读正文、只写本范围审核报告，不改总词表、不改正文，也不再派子代理。

用户只授权审核子代理时，主代理仍可串行翻译各线，完成后新建相应审核代理。用户未授权任何子代理、明确禁止或宿主无法创建时，原负责人在翻译完成后另做同样四类的一轮对照检查，记录 `same_agent` 或能力降级，不伪造独立审核。

## 3. 一轮审核如何读完并结束

同线只占一个子代理名额：主代理先确认译者已保存产物、登记原线程／恢复依据并结束释放，再新建审核者。只让译者“等待”不算释放；已完成却仍占槽导致满额时，由主代理发消息让它自行结束，再核对状态，具体见 workflow.md 第 2.1 节。共通由主代理翻译时无需结束主代理，但审核期间主代理也不改冻结稿。先冻结所审正文和词表版本，审核期间不让译者并发覆盖它。个人线通常先完成统一新增术语及必要返修，再审这份稿，避免刚审完旧词就大范围改词；不要同时保留“术语返修前一审”和“返修后二审”。

同一审核代理按真实场景／分支顺序分批读完指定范围，保留必要前后文。整线超出上下文时按批保存覆盖和源文引用、恢复后继续同一轮；不为每批新开审核代理，不重头循环审已覆盖全文。所属普通／坏结局和范围内选项也纳入清单，不能用搜索命中或抽检代替全量阅读。

报告只列有证据的问题和精简覆盖记录。无问题的段落不逐条写“通过”，也不回传全部译文。每个问题包含：`issue_id`、类别、线路／文件／稳定 ID、最小原文证据、当前译文、简短错误说明，以及可选最小修改建议。原文也不能确定时标待定，不能强判错误。重复原因可合并报告，但保留受影响位置。

审核者必须完整审完所分配的整条线，才一次交付完整问题清单和覆盖；内部可分批落盘，但不边审边让译者返修。主代理确认报告可读且覆盖完整后，必须确认审核代理已结束并释放名额，再恢复原译者处理完整报告。审核者不得自行召唤译者；名额不足或释放未确认则排队，不同时保持同线两个未释放线程。**不默认召回审核者复核、不新建第二轮审核代理、不让主代理再完整审一遍各线。** 请求额外独立复审须由用户明确提出，不能以“保险”为名自动扩大成本。

## 4. 原译者修改，不增加第三个审核阶段

主代理完成上述交卷与释放步骤后，优先按登记的线程 ID 恢复原翻译代理；模型／推理档和必要上下文核对后再发完整修正任务。共通则由主代理本人处理。原线程确实无法恢复时才用同配置、同线路替补，并如实记录；详细释放、队列和异常规则见 [workflow.md](workflow.md) 第 2.1 节。

原负责人对照原文处理问题：共通由主代理，个人线及真结局由各自原译者。建议不是自动正确的答案；有依据就修改，误报则保留原译并记录最小反证。涉及总词表或跨线影响时由主代理裁决，再通知受影响负责人。

修完检查实际差异、相关原文、邻近对白和控制符；影响指代、事件因果或人物状态时，检查受影响的后续语境。明确问题来自反复使用的错误前提时，原译者搜索并修正全部受影响处，不只修报告示例；这仍是定向修订及自检，不自动加一次全线独立审核。

问题报告保留为审核者的只读产物，原译者将处理结果写入自己的修订记录。状态使用 `open / fixed_selfchecked / dismissed_with_evidence / unresolved`；区分“原译者修正并自检”与“审核者已独立复核”，后者未做就不得填写。

修正和局部自检完成后保存记录；译者为子代理时由主代理再次确认它已结束并释放名额，不留在本线待命，不把审核者召回。共通等由主代理亲自翻译的范围不结束主代理自身。无问题且无待改项时无需恢复译者做空转。

若重大问题无法依据原文解决，如实保留未决与交付限制，不假称通过；不因用户控制成本而漏报，也不擅自增加付费审核轮次。

审核后新增或改变术语时，同样由原负责人只改命中语境并局部自检，不重开整线审核。审核后补入以前根本未审的新场景／缺失区段，应在同一审核任务中仅补齐该未覆盖范围（能恢复则恢复；不能恢复则仅替补缺失范围），不重审已覆盖全文；补审也先结束释放译者，再恢复／补建审核者，结束并释放后才能恢复译者。这是补齐一轮覆盖，不是第二轮全线复审。

## 5. 压缩、中断与代理替换

每个场景／合理批次完成后增量保存：实际落盘位置、下一个单元、翻译／自审／纠错覆盖、源译及词表版本、当前人物／关系／称呼阶段、未完动作或对白、必要原文引用、未决项。先写产物再更新完成位置；不重复写长摘要和巨型台词清单。主动交接前保存，突然压缩则依靠最近可靠检查点。

发生新会话、压缩、代理替换或进度不确定时，先暂停续写：
1. 读取当前角色所需规则、项目索引、本线状态和适用词表，核对实际文件及版本。
2. 回读最后可靠检查点附近的必要原文与译文，确认谁说话、人物关系、信息阶段及衔接；摘要冲突时以原文为准。
3. 核对已落盘与未完成 ID。标记最后可靠检查点后未经自审的内容，以及恢复后首批内容，完成接缝核对及该批自审后再推进状态。

回读范围以足够判断为准，不机械只看最后几句；同样不因压缩就从头翻整条线。审核代理中途压缩也保留本轮覆盖与证据，恢复后从未审范围继续，不恢复译者聊天来“补记忆”。

本技能不是自动压缩监听器，不安装全局钩子，不保证能捕获所有压缩。最终一次纠错需要留意已有恢复边界，但不为每次压缩另起一名审核代理。

## 6. 记录与交付

沿用已有资料，或使用 `assets/route-state.template.json` 与 `assets/review-batch.template.json`。只记录范围、真实审核者／模型／隔离状态、所审原译文和词表版本、四类检查覆盖、问题与限制；模板为空不是已完成证明。

保留“审核过的稿件版本”，不要在原报告里偷换成修订后版本。最终交付记录使用“已审版本＋实际修订清单＋修改处自检＋最终版本”，据此证明工作做到了哪一步。原文或正文变化时标记受影响范围，由原译者核对差异和必要上下文；没有影响的新增词不触发全作重查。无法界定差异时如实标明验证不足，不自动重启整线审核。

结束／释放证据与恢复身份由主代理记录在 project.json 的调度登记，不回写审核者的只读问题报告。主代理交付前检查范围和四类纠错覆盖、术语处理、问题处理记录、遗留占槽线程及适用技术检查；不再额外安排全文文风审读或跨范围内容终审。确有未解决的跨线问题才定向处理。对最终实际文件运行已有结构／映射／回填检查，游戏实测未做则单列未测。

报告可写：“整线原译文已完成一次独立纠错；已报问题由原译者修正并局部自检；未另做独立改后复核。”不能写成“每句经两名代理反复验收”或“保证零错译”。
