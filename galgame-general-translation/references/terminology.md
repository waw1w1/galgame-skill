# 术语协议

## 收录边界

收录需要跨句、跨场景或跨路线稳定的名称／概念：人名与昵称、地名、国家／学校／组织／社团／公司，特定身份／职位／阶级，魔法／能力／技能／招式／状态，武器／道具／货币，种族／宗教／制度／历史事件，游戏系统／菜单／UI，网络昵称，作品特有概念，具有回收作用的重复台词／口号／固定句式，以及确有领域含义的专业词汇。

不把所有名词都入表。普通“桌子、今天、吃饭”、无特殊意义的一次性修饰和一般动词不用锁译；普通称呼的处理策略放人物／风格资料，承担身份或关系变化时才建条件词条。不要为了让表显得完整而堆候选。

## 一个总表，按语境生效

主代理唯一写入总表；扫描与翻译代理只写本线文件。总表按概念、义项和使用条件管理，不是“原文字符串→唯一中文”的全局替换字典。

同形异义分开，异形同义可合并。称呼、隐藏身份和揭示后的真名须有路线／阶段／说话者条件；收进总表不等于适用全作。同一概念的真正同义译法需统一，合理的条件变体不应被误判成冲突。

并行翻译使用主代理发布的只读版本；总表外新词暂存本线增量，不边译边改其他线路的基准。应用顺序：匹配当前条件的总表词条 → 不与其冲突的本线暂定词条 → 临时拟译并加入本线表。发现已有总表词条可能错了，记“挑战现有词条”及证据，不静默覆盖。

## 默认数据格式

已有可靠格式就沿用。新项目用 UTF-8 JSONL（一行一个 JSON 对象），换行写在字符串转义中；相同表内 `id` 唯一，跨候选文件加路线前缀。仅确有数据时创建文件。

所有词条字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 本记录稳定 ID；候选用 `路线:编号`，主代理发布后用全局 ID |
| `source` | 原文主要写法 |
| `target` | 确认／建议译法；扫描无法判断可为空，并标未决 |
| `meaning` | 一句足够区分概念和义项的定义，不写整段剧情 |
| `scope` | `global` 或明确路线、场景／阶段、说话者等使用条件 |
| `status` | `candidate`（预扫）、`provisional`（线内使用）、`approved`（主代理确认）、`unresolved` |

按需字段：`aliases` 原文别名数组；`canonical_id` 已知关联总表 ID；`evidence` 最小证据数组；`occurrences` 本次扫描／翻译已发现的 `文件#文本ID` 数组；`note` 短理由／不确定处。不要维护重复的全文摘录或逐句推理。

证据示例：`{"location":"route-a/03.json#104","quote":"原文的定义性短句","note":"指组织，不是地名"}`。通常一个定义性原句，冲突才补第二例；只给出词本身而无上下文不足以裁决。用途例句、计数不是全量命中清单，后续修订仍需搜索全部相关单元。

供格式参考的纯虚构例子：

```json
{"id":"a:001","source":"星環局","target":"星环局","meaning":"作品中的观测机构","scope":"global","status":"candidate","evidence":[{"location":"a.json#42","quote":"星環局は観測を担う機関だ。"}],"occurrences":["a.json#42"]}
```

可选的只读辅助命令：

```text
python "<skill目录>/scripts/term_audit.py" 总术语表.jsonl 本线扫描.jsonl 另一线增量.jsonl --report 审核候选报告.json
```

它检查格式、列出字面重合／关联 ID 的候选组，不判断“同一概念”，不做翻译、不合并词表。无需 Python 时可直接按同一协议人工审阅，不为运行辅助脚本强装依赖。

## 扫描代理交付契约

只处理分配的单一线路，读取完整指定原文范围与共通阶段的总表。可分块顺序读，不以关键词搜索命中代替全线扫描。无需输出正文译文、全文摘要、逐句解释或穷尽人物档案。

记录扫描覆盖的文件／ID 范围、未覆盖范围及原因；提取新增术语、已有译法的反证和本线特殊使用条件。已正确存在且没有新证据的词不重复提交。候选附最小证据、拟译／未决状态；无法可靠拟译也必须留下词与位置，不能因不确定而漏掉。

把候选写入本线 `scan.jsonl`，覆盖记录写入本线状态。返回路径、覆盖情况、候选数和少量真正阻塞问题。扫描权限只限原文读取与本线扫描产物写入，不改译文、总表或其他路线文件。没有文件写入能力时返回同样结构，由主代理落盘并注明代写。

## 主代理裁决

先判定是否同一概念，再判断是否同一使用条件，最后定译法。以原文证据、有效上下文和用户确认方案为准，不按“多数票”“先出现”“最便宜模型的信心”或脱离语境的中文好听程度投票。

无冲突的新词审核后合并；同义且同译去重并保留来源；同义异译选择统一译法；同形异义／合法条件变体分开保存。旧总表不是不可纠错，后文证据充分时可修订，但必须列出受影响的共通线及全部个人线。

材料不足时优先按引用读取局部原文，确需原线路代理补证时由主代理排队恢复，先确认本线其他子代理已结束释放；不在本线审核中并发唤醒译者。只索要定义句、邻近几句或指定场景，不把整条线重新交给主代理。保留原作有意歧义；实在未决的词使用保守可回退方案并显式标记，不能伪造已确认。

决策只记录：关联候选 ID、采用词条／译法、作用范围、简短依据、受影响路线／单元、是否需要返修。非重复新词也须经主代理确认，不让脚本自动批准。

## 增量合并与定向返修

本线翻译中新词立即入本线 `terms.local.jsonl`，并持续用该暂定译法；不每遇一词就呼叫主代理。只有将造成大量不可逆误译的错误才即时上报。记录位置供回查，不维护完整重复词表。

各个人线完成后，主代理批量审核全部本线表，对照基准总表并发布新版本。为受影响线路发出精确任务：旧→新、概念／使用条件、相关原文写法、已知位置、必须搜索的范围；没有冲突的线路不重跑全文翻译。

主代理按本线单槽位顺序恢复原线路翻译代理，再按原文＋语境修改所有命中并复核邻句、称呼和标签；完成后结束释放。目标线正在审核时先登记待办，待该审核完整交卷并结束后再改，不能抢改冻结稿。不能仅对中文做无条件字符串替换；同字不同义、引用、假名、身份阶段可能必须保留。命中索引只作起点，还要搜索总表别名与既有译文，避免漏修。

提交实际修改单元、无需修改的候选及理由、自检结果和词表版本。主代理只将已确认增量标为并入，保留决策及修订痕迹。术语修订不代替一次整线纠错：尚未审核的线路先完成术语修订再审一次；已经审过的范围由原译者只改受影响语境并局部自检，保留所审版本与新版本差异，不召回审核者、不额外重审整线。真结局新增术语同理，必要时通知共通／个人线负责人定向回修。
